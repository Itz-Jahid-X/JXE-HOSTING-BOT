## ✨ What Is JXE Hosting Hub?

**JXE Hosting Hub** turns a Telegram bot into a lightweight
project-management and hosting control center.

Upload a project as a `.zip`, select its entry file, launch it, inspect
logs, manage files, configure `.env` variables, monitor resources,
restart crashed services, and create backups --- all through Telegram's
interactive dashboard. fileciteturn1file2L112-L163

## 🎨 Telegram UI

The project uses a consistent action-based button styling system:

  Action                                 Style
  -------------------------------------- ------------
  🚀 Deploy / Start / Install / Create   🟢 Success
  🧭 Navigation / Management / Info      🔵 Primary
  🗑 Delete / Stop / Remove / Clear       🔴 Danger

The implementation maps positive actions to `success`, destructive
actions to `danger`, and remaining management/navigation actions to
`primary`. fileciteturn2file6L517-L541

## 🖥️ Runtime Engines

The launcher supports these project entry types:

``` text
🐍 .py    → Python
🟨 .js    → Node.js
🐚 .sh    → Bash
🌐 .html  → Python HTTP server
```

Python projects are launched with the current Python interpreter,
JavaScript projects with Node.js, shell projects with Bash, and HTML
projects through Python's HTTP server. fileciteturn1file0L109-L119

## 🔌 PORT

For web/server projects, the bot automatically finds a free local TCP
port and exposes it to the project through:

``` env
PORT=<assigned-port>
```

The help flow explicitly documents using the `PORT` environment variable
for the assigned port. fileciteturn2file1L151-L163

## 🛡️ Security Model

JXE Hosting Hub includes several project-isolation checks:

``` text
ZIP Upload
   │
   ├── ❌ Absolute paths
   ├── ❌ ../ traversal
   ├── ❌ Symlink entries
   ├── ❌ Outside-project resolution
   │
   ▼
Safe Project Directory
   │
   ├── 🔒 Restricted HOME
   ├── 🔒 Restricted USERPROFILE
   ├── 🔒 Project TEMP
   └── 🔒 Reduced inherited environment
```

The runtime environment intentionally does not pass the hosting bot's
complete environment/secrets to user projects.
fileciteturn1file3L291-L352 fileciteturn1file1L132-L182

> **Important:** This is a project-level protection layer, not a
> replacement for OS/container-level sandboxing.

## 🧩 Configuration

The bot expects `config.json` beside `main.py`. `BOT_TOKEN`, project
storage location, metadata file and owner ID are loaded from
configuration, with `BOT_TOKEN` also supported through an environment
variable. fileciteturn2file0L38-L62

Example structure:

``` json
{
  "bot_token": "YOUR_BOT_TOKEN",
  "owner_id": 123456789,
  "base_dir": "projects",
  "meta_file": "projects_meta.json",
  "default_online_days": 2,
  "default_project_limit": 1,
  "max_concurrent_projects": 8,
  "queue_enabled": true,
  "auto_restart_default": true,
  "deploy_enabled": true,
  "dynamic_animation_enabled": true,
  "show_live_status": true
}
```

Use your real values for the deployment. **Never publish your bot token
in GitHub.**

## ▶️ Quick Start

### 1. Clone

``` bash
git clone https://github.com/YOUR_GITHUB_USERNAME/YOUR_REPOSITORY.git
cd YOUR_REPOSITORY
```

### 2. Install Python dependencies

At minimum, the source imports:

``` bash
pip install pyTelegramBotAPI requests urllib3 psutil
```

`psutil` is optional at runtime in the source; when unavailable, the bot
falls back from advanced process/system metrics.
fileciteturn2file0L10-L36

### 3. Create `config.json`

``` json
{
  "bot_token": "YOUR_BOT_TOKEN",
  "owner_id": 123456789,
  "base_dir": "projects",
  "meta_file": "projects_meta.json"
}
```

### 4. Start

``` bash
python main.py
```

On startup, the bot removes any webhook, verifies the Telegram
connection, and enters long polling with automatic reconnect handling.
fileciteturn3file0L303-L326
